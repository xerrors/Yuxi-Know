# 0.8.0 更新说明

本页面向准备试用或部署 0.8 的用户，汇总相对 `v0.7.3` tag 的变化。0.8 主要完善知识检索与来源核对、多智能体分工与人工干预，并通过 MCP、公开 API 和 CLI 接入已有工具。

更新项按用户可观察的结果合并，连续修复和内部重构不重复列为功能。定时任务、用户 Memory、主动上下文压缩、基础子智能体、API Key 和执行审计是既有能力，本页只列出相关增强。历史版本见[版本变更记录](../changelog.md)。

## 升级概览

| 方向 | 主要变化 | 使用价值 |
| --- | --- | --- |
| 多智能体协作 | 成员使用独立会话，可分派任务、互发消息、等待结果并共享项目文件 | 将复杂任务分工处理，分别查看成员状态和结果 |
| 排队与人工干预 | 输入独立持久化；普通消息顺序执行，运行中可优先引导；支持逐条取消、停止全部和继续队列 | 补充要求、纠正方向，并控制后续任务的执行 |
| 检索与溯源 | 向量、BM25 和混合检索，配合关键词约束、高亮、正文行号和回答引用 | 兼顾语义与精确词查询，并从答案继续核对原文 |
| 知识接入与开放 | 飞书在线只读连接；内置五个只读知识工具的 MCP 服务 | 使用已有飞书资料，并让外部 Agent 查询 Yuxi 知识库 |
| Agent 与 Skills | 私有与授权共享、专属 Skill、ZIP 导入、完整包编辑与修订冲突检查 | 将提示、脚本和模板组织为可复用能力 |
| 身份与工具授权 | 完善 OIDC、资源权限和 APP 作用域；远程 MCP 支持个人 OAuth 连接 | 管理团队访问范围，并按个人授权使用适配的远程服务 |
| 执行与交付 | 每用户持久 Cube VM；多图输入、图表、图文卡片和简短表单 | 复用软件与配置，收集任务条件并查看文件和可视化结果 |
| 集成与可靠性 | Public v1 Session 协议、npm CLI、断流恢复、明确失败状态及只读历史 | 接入应用和脚本，并保留任务结果与工作记录 |

具体能力及适用边界见下文；飞书连接使用管理员配置的身份，个人 MCP OAuth 的供应商兼容性需逐项验证。

## 部署与兼容范围

::: warning 部署边界
0.8 面向全新部署，不提供从 0.7.x 或开发期旧数据库原地升级的程序。重要数据先成套备份 PostgreSQL、MinIO 和用户文件，并保留原部署。请使用独立数据目录试用，不能通过修改 Schema 版本标记绕过检查。
:::

- **数据库与索引**：PostgreSQL 当前基线为 business 1、knowledge 1，`app-init` 只初始化空库；API 与 worker 对版本不符的数据库拒绝启动。Milvus 与 PyMilvus 切换到 3.0.2，配套 etcd 3.5.25、Woodpecker 日志队列与 MinIO 对象存储；旧索引与对象不提供自动转换。操作以[生产部署](../../advanced/deployment.md)为准。
- **执行节点**：Agent 执行环境固定为 CubeSandbox 0.7.3 的 Linux/KVM 用户 VM，需要专用节点、用户模板以及与 API/worker 共享的 Workspace、Skills 目录。macOS/Windows 上运行应用也需要可访问的 Linux/KVM 节点。旧 Docker/Kubernetes provisioner 和 Docker socket 接入已移除，见[沙盒配置与运维](../../advanced/sandbox-operations.md)。
- **路径与环境数据**：VM 工作区固定为 `/home/user/workspace`，授权 Skill 投影为只读 `/home/user/skills`。旧挂载路径、附件引用和 checkpoint 不自动转换；VM 重建清除 Home 中的软件与配置，宿主 Workspace 与 Skills 保留。
- **外部客户端**：Agent 对话统一使用 `/api/v1/agents/sessions` 资源、Input 回执和公开事件；知识库查询统一使用 `/api/v1/knowledge/tools`。旧 Conversation、external 查询入口及响应字段不保留兼容层，集成方应按[Agents API 快速开始](../../intro/agents-api-quickstart.md)和[知识库 API](../../advanced/knowledge-base-api.md)调整客户端。
- **命令行**：CLI 改为 Node.js 22+ 的 npm 包 `@xerrors/yuxi`，npm 包版本为 0.1.0，独立于应用版本发布。旧 Python CLI 的 TOML 配置不自动导入，新 CLI 使用 `~/.yuxi/config.json`，需要重新配置实例并登录，见[CLI 使用指南](../../intro/cli.md)。

新 CLI 提供多实例配置、API Key/浏览器登录、身份状态、Agent 目录、终端聊天与 SSE 恢复、附件及图片提交、知识库查询和 JSON 输出。附件先通过 `file upload` 上传草稿，再用 `thread send` 提交；旧 CLI 的 eval、Langfuse、本地 HTML Chat 与原 `upload` 命令不保留，审批与回答等待点需在网页继续。

## 会话、排队与多智能体协作

- **复杂任务可以分工处理**：协作成员拥有独立上下文和 Session，可创建子会话、互发消息、提交工作、等待并读取指定任务结果。新成员接收明确的任务描述，成员共享 Project 工作目录及整树四个执行名额，等待协作时释放执行资源。
- **用户可以进入具体成员推进工作**：协作列表展示成员层级、运行状态和人工待办，支持在侧栏打开成员会话回答问题、审批或发送引导。输入区可提及当前用户可运行的 Agent，由当前智能体按任务需要创建协作会话。
- **追加任务与调整方向分别处理**：每次提交保存独立 Input 和幂等回执，消费后生成正式消息与执行记录。普通追加输入按 FIFO 单条派发；运行中可用 steer 调整方向，连续就绪的 steer 在模型调用或工具批次完成后的安全边界合并处理。已经发往外部工具的操作不会因 steer 自动撤销。
- **停止与继续有明确范围**：待处理输入可逐条取消或转为引导；取消单个 Turn 只影响该任务，“停止全部”取消整树在途工作并暂停排队输入。显式继续队列会重新派发待处理工作。等待用户回答或审批时，普通提交被拒绝，需先处理对应等待点。
- **刷新与切换后保留正确的工作记录**：历史分页、实时流和断线恢复使用同一会话内容投影，最终结果读取指定 Turn 的 result Run。修复串会话更新、恢复后旧事件收尾及排队图片、附件归属问题；切换会话保留各自草稿、侧栏和滚动状态。
- 新会话可在首次执行时自动命名。默认最大执行步数调整为 2000、上下文压缩阈值为 256K；已有显式配置继续优先。模型重试与摘要失败保留真实失败状态。

操作说明见[会话协作](../../agents/session-cooperation.md)，运行状态与恢复语义见[Agent 运行机制](../../mechanisms/agent-runtime.md)。本节合并[生命周期](../decisions/implemented/2026-09-29-agent-lifecycle-framework.md)、[协作](../decisions/implemented/2026-10-03-session-cooperation.md)、[输入投影](../decisions/implemented/2026-10-10-input-message-projection.md)及[前端状态收敛](../decisions/implemented/2026-10-15-session-item-input-ownership.md)的最终行为。

## 知识检索、来源阅读与飞书连接

- **语义问题与精确词查询可以分别配置**：Milvus 知识库支持向量、BM25 与混合检索，可配置必含词、排除词、完整短语及高亮，适用于术语、型号、编号等需要保留精确词的查询。结果区分余弦、BM25 和融合分数，支持展开完整片段、点击文件名打开来源。
- **从回答继续核对来源**：分块保留解析正文的来源行号，检索与文档阅读共用坐标；回答通过来源胶囊预览引用并定位文档，已完成回答的来源标注独立保存。旧分块缺少行号时不能恢复精确位置，也不承诺所有 PDF 都有页码。检索质量仍需用实际语料和模型评估。
- **飞书已有资料可以在线读取**：新增飞书知识库只读连接，使用管理员配置的用户 token 搜索指定 Wiki 空间，并分页读取新版普通文档的实时纯文本。连接不在本地解析、同步或向量入库，减少维护文档副本的步骤。token 到期需管理员更换；共享连接使用配置身份的飞书权限，旧版文档、表格、附件与快捷方式不在阅读范围内。
- **外部 Agent 可以使用 Yuxi 知识库**：API 内置 `/api/mcp` 无状态 Streamable HTTP 服务，与 Agent、CLI 和 Public HTTP 复用五个只读知识工具：列库、检索、按文件名搜索、打开正文和文内查找。客户端使用 API Key，按绑定用户的知识库权限读取结构化结果与分页信息，无需另起 MCP 服务进程。
- 新增“知识库问答”预设。知识检索失败保留工具错误状态，正常空结果保持成功；文档批次存在失败文件时，后台作业报告失败和有限明细。自动入库结束后刷新文件列表与统计，索引结果按 PostgreSQL 当前可见文件过滤，避免已删除文件的残留向量继续进入结果。

配置与限制见[知识库 API](../../advanced/knowledge-base-api.md)和[知识库 MCP 接入](../../advanced/knowledge-mcp.md)。本节合并[Milvus 3 检索](../decisions/implemented/2026-10-02-milvus-3-text-retrieval.md)、[来源行号](../decisions/implemented/2026-10-09-chunk-source-lines-and-retrieval-preview.md)、[MCP](../decisions/implemented/2026-10-15-knowledge-mcp.md)及[飞书连接](../decisions/implemented/2026-10-16-feishu-readonly-connector.md)的最终行为。

## Agent、Skills、权限与身份

- **Agent 可按团队需要私有使用或授权共享**：主 Agent 默认私有，所有者可管理；管理员可按授权共享，系统管理员可治理共享资源。角色限定可管理的能力，资源范围限定可访问的对象；模型请求、工具调用与恢复执行重新核对当前授权。
- 资源选择统一使用“全部”或明确列表，空列表表示不选择。工具、知识库与共享 Skills 默认全部，MCP 和预加载 Skills 默认不选择；实际运行始终与当前用户的授权取交集，个人 Skill 保留在个人工作区。
- 没有已保存偏好时，Memory 默认开启，设置页提供“查看 Memory”入口；用户已明确保存的关闭状态继续生效。
- **操作方法和配套文件可以随 Agent 复用**：Agent 支持绑定专属 Skill，创建时可导入 Skill ZIP；共享与专属 Skill 支持在线编辑完整包，保存时检查修订冲突，避免覆盖他人更新。专属 Skill 还支持显式发版、查看和恢复完整历史包，恢复覆盖当前文件与依赖；普通 Skill 不提供历史版本入口。远程安装草稿区分可确认条目与失败项，支持部分失败处理。
- 用户目录区分系统用户与 APP 终端用户。Agents API Key 绑定 APP，终端用户、Thread、附件与执行按 APP 作用域隔离；移除模拟他人登录入口。账号管理维持至少一个有效系统管理员，角色调整只升不降。
- 完善 OIDC discovery、JWKS、PKCE、回调及身份绑定校验。退出登录撤销 Yuxi 本地凭据，不主动退出企业认证中心；配置与部署条件见[OIDC 认证](../../advanced/third-party-auth.md)。
- Agent 被删除或撤回访问后，原用户仍可读取自己已有会话的历史，输入与继续执行入口进入只读状态。网络或服务错误单独提供重试，历史读取继续遵循原用户和 APP 权限。
- 反馈以已完成 Turn 的最终 Run 为对象，支持用户赞/踩、Agent 改进标记及系统管理员只读查看，为人工分析提供线索。反馈不会自动训练或修改 Agent；消息级旧反馈接口与满意度统计保持移除，见[Agent 反馈](../../advanced/agent-feedback.md)。

权限边界见[资源权限](../../mechanisms/resource-permissions.md)，安装与编辑见[Skills 管理](../../agents/skills-management.md)。本节合并[资源权限](../decisions/implemented/2026-10-03-resource-permission-convergence.md)、[专属 Skill](../decisions/implemented/2026-10-03-agent-bound-skill.md)、[完整内容提交](../decisions/implemented/2026-10-05-skill-content-commit.md)及[OIDC 边界](../decisions/implemented/2026-10-13-oidc-production-boundaries.md)的最终行为。

## 远程 MCP 与个人账号授权

- 超级管理员统一配置远程 MCP，开放后在 Agent 配置中选择。共享 headers 模式使用配置身份；个人 OAuth 模式由每名用户连接自己的资源账号，平台登录与资源授权分别管理。
- 用户在扩展页面查看、连接和断开本人账号。个人凭据在服务端加密保存，刷新与断开按用户连接串行处理；实际调用重新检查当前用户、服务配置、工具开关和连接。未连接服务不进入可用工具集合，普通聊天继续；相关 Skill 的依赖在执行边界校验。
- 断开或修改授权配置使旧授权事务失效，个人授权不回退为管理员凭据。本地断开不等于远端供应商撤销授权，也不能收回已经送达远端的请求。
- 个人 OAuth 适用于当前发现、注册、PKCE 和传输约束下的服务；其他服务需分别验证。部署需要通用凭据密钥和固定回调来源，见 [MCP 集成](../../agents/mcp-integration.md)。

Yuxi 向外提供的知识库 MCP 与这里的远程工具接入是两条链路：前者让外部客户端读取 Yuxi 知识，后者让 Yuxi Agent 调用外部服务。个人连接及执行授权见[MCP 授权与运行身份](../../mechanisms/mcp.md)，未复验范围见[验证与已知限制](#验证与已知限制)。

## 图片、交付物与工作区体验

- **图片可随问题直接提交**：单条消息支持最多 10 张图片直读；排队和会话切换保持图片与原提交归属。文件仍通过附件准备和确认链路进入工作目录。
- **结果可用图表、图片和图文卡片展示**：内置 `chat-widgets` Skill 按需展示图表、图片组及图文组合，沙盒图片可使用实际虚拟路径。工具结果中的文本与图片按原顺序显示，受保护图片通过统一鉴权读取，支持放大查看。截图进入正文与文件登记为交付物是两个独立动作。
- **任务条件可在简短表单中一次填写**：聊天组件支持文本输入、多行文本、单选、日期及提交按钮。提交作为独立普通用户消息继续任务，保留编辑器中的草稿和附件；发送中、失败和已发送有明确反馈。表单仅收集回答，按钮只支持固定的发送消息动作，不直接执行任意工具或业务写入；实际触发和输出仍受模型行为影响。
- 修复最终正文被过程折叠隐藏、交付卡片与重复过程展示的问题。图片缩略图限制展示高度；文件预览、下载与 Agent 实际读取的用户挂载保持一致，Skill 投影缺失时明确失败。
- **软件与配置可跨会话复用**：每名用户使用一个持久 Cube VM，同用户会话共享软件、Home 和配置；项目分别管理工作目录和任务结果。VM 以普通账号执行、无 sudo 权限，空闲时休眠；重建清除 Home，Workspace 与授权 Skills 保留。同用户项目不拥有各自独立的 VM，见[沙盒机制](../../mechanisms/sandbox.md)。
- 新建 Project 的默认工作目录使用 `projects/YYYYMMDD/<六位标识>`，重名时添加后缀；手动选择的目录继续按用户工作区边界校验。用户环境变量在每段 Run 开始时读取为快照，同次执行的命令使用同一份配置。
- 模型、审批、附件和项目选择入口共用弹层行为，模型目录显示加载与失败重试；主题、图标、头像及扩展卡片的外观统一。修复快速切换预览、全局搜索、上传期间切换会话及会话路由的迟到响应问题。
- “+”和“@”共用添加菜单，集中选择附件、图片和可引用资源；网络搜索设置集中管理搜索与正文抓取供应商及凭据，按实际配置绑定可用工具。支持 Tavily、DeepSeek 搜索和正文读取，以及豆包搜索；不同供应商的参数限制分别校验。
- 提供浏览器自动化 Skill 推荐，分别连接上游 `agent-browser` 与 `playwright-cli`。安装 Skill 后仍需按其指南在用户 VM 安装 CLI 依赖；跨会话登录状态由实际 profile/session 配置决定，不能视为默认永久保留。

对话内 HTML Preview 已移除，旧 `html:preview` 围栏显示为普通代码；HTML 文件仍可作为交付物在文件预览中打开。知识库思维导图、旧 SubAgent 专用后端/目录、Agent 待办清单工具及身份操作日志机制也已移除；知识图谱和协作成员的人工待办继续提供。

## 运行与工程维护

- 后端收敛为 `backend/yuxi` 单包，按业务域组织 services、repositories 和 models；API、worker、基础设施与 Schema 初始化保持明确边界。前端统一为 `frontend/`，按 app、pages、modules、shared 分层；自定义脚本和 Compose 命令需使用当前目录及服务名。
- 工具结果、审计、历史、用量与反馈围绕明确的 Turn/Run 事实读取，减少独立工具表和重复内容投影。后台作业统一为 BackgroundJob；PostgreSQL 持久意图、执行 owner 与租约拥有恢复结果，Redis 负责投递与短期事件。
- 文档解析生成完整 Markdown 目录，图片等资源随目录发布，上传、OCR、预览与文件操作在各自边界校验。共享存储查询限制并发，worker 和 API 保持可观察的启动、失联与关闭结果；readiness 不替代真实业务验证。
- 质量检查覆盖工程契约、后端 unit、Ruff、Web、依赖审计、文档及真实运行链路。开发分支匹配 `develop/**`，保留按改动路径触发检查，运行链路需要带 `yuxi-cube` 标签且能访问执行节点与共享文件的自托管 runner。
- 更新文档解析、MCP、Vue、HTML 清理及 YAML 等依赖的安全补丁，并同步生产锁文件；Markdown 自动链接和公式渲染依赖的已知告警已修复，生产依赖审计通过。
