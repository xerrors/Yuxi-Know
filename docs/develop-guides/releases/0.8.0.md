# 0.8.0 更新说明

本页汇总相对 `v0.7.3` tag 的 0.8 变化。当前候选版本为 `0.8.0.beta1`，处于发布准备阶段；更新项按最终用户行为合并，连续修复和内部重构不重复列为功能。历史版本见[版本变更记录](../changelog.md)。

## 部署与兼容范围

::: warning Beta 部署边界
0.8.0.beta1 面向全新部署，不提供从 0.7.x 或开发期旧数据库原地升级的程序。重要数据先成套备份 PostgreSQL、MinIO 和用户文件，并保留原部署。请使用独立数据目录试用，不能通过修改 Schema 版本标记绕过检查。
:::

- **数据库与索引**：PostgreSQL 当前基线为 business 4、knowledge 1，`app-init` 只初始化空库；API 与 worker 对版本不符的数据库拒绝启动。Milvus 与 PyMilvus 切换到 3.0.2，配套 etcd 3.5.25、Woodpecker 日志队列与 MinIO 对象存储；旧索引与对象不提供自动转换。操作以[生产部署](../../advanced/deployment.md)为准。
- **执行节点**：Agent 执行环境固定为 CubeSandbox 0.7.3 的 Linux/KVM 用户 VM，需要专用节点、用户模板以及与 API/worker 共享的 Workspace、Skills 目录。macOS/Windows 上运行应用也需要可访问的 Linux/KVM 节点。旧 Docker/Kubernetes provisioner 和 Docker socket 接入已移除，见[沙盒配置与运维](../../advanced/sandbox-operations.md)。
- **路径与环境数据**：VM 工作区固定为 `/home/user/workspace`，授权 Skill 投影为只读 `/home/user/skills`。旧挂载路径、附件引用和 checkpoint 不自动转换；VM 重建清除 Home 中的软件与配置，宿主 Workspace 与 Skills 保留。
- **外部客户端**：Agent 对话统一使用 `/api/v1/agents/sessions` 资源、Input 回执和公开事件；知识库查询统一使用 `/api/v1/knowledge/tools`。旧 Conversation、external 查询入口及响应字段不保留兼容层，集成方应按[Agents API 快速开始](../../intro/agents-api-quickstart.md)和[知识库 API](../../advanced/knowledge-base-api.md)调整客户端。
- **命令行**：CLI 改为 Node.js 22+ 的 npm 包 `@xerrors/yuxi`，候选源码包版本为 0.1.0，独立于应用版本发布。旧 Python CLI 的 TOML 配置不自动导入，新 CLI 使用 `~/.yuxi/config.json`，需要重新配置实例并登录，见[CLI 使用指南](../../intro/cli.md)。

新 CLI 提供多实例配置、API Key/浏览器登录、身份状态、Agent 目录、终端聊天与 SSE 恢复、知识库查询及 JSON 输出；旧 CLI 的 eval、Langfuse、本地 HTML Chat 与上传命令不在当前包内。

## 会话、排队与多智能体协作

- 每次提交保存独立 Input 与幂等回执，消费后才生成正式消息和执行记录。普通追加输入按 FIFO 单条派发；运行中可用 steer 调整方向，连续就绪的 steer 在安全边界合并处理。取消与转引导针对指定待处理输入，等待回答或审批时禁止普通提交。
- 多智能体统一为拥有独立上下文的协作 Session。成员可创建子会话、互发消息、提交新工作、等待任务并读取指定任务结果；新成员只接收明确任务描述，不复制父历史。成员共享 Project 工作目录及整树四个执行名额，等待协作时释放执行资源。
- 协作列表支持查看成员层级、运行状态和人工待办，并在侧栏打开成员会话进行回答、审批或 steer。取消单个 Turn 只影响该任务；“停止全部”取消整树在途工作并暂停排队输入，显式继续队列会重新派发待处理工作。
- 历史分页、实时流和断线恢复合并到同一会话内容投影，最终结果始终读取指定 Turn 的 result Run。修复串会话更新、恢复后旧事件收尾、排队图片及附件归属问题；会话切换保留各自草稿、侧栏和滚动状态。
- 新会话可在首次执行时自动命名，支持在输入区提及可运行的 Agent。默认最大执行步数调整为 2000、上下文压缩阈值为 256K；已有显式配置继续优先。模型重试与摘要失败形成真实失败结果，避免把错误文本当作成功回答。

操作说明见[会话协作](../../agents/session-cooperation.md)，运行状态与恢复语义见[Agent 运行机制](../../mechanisms/agent-runtime.md)。本节合并[生命周期](../decisions/implemented/2026-09-29-agent-lifecycle-framework.md)、[协作](../decisions/implemented/2026-10-03-session-cooperation.md)、[输入投影](../decisions/implemented/2026-10-10-input-message-projection.md)及[前端状态收敛](../decisions/implemented/2026-10-15-session-item-input-ownership.md)的最终行为。

## 知识检索、来源阅读与飞书连接

- Milvus 知识库支持向量、BM25 与混合检索，可配置必含词、排除词、完整短语及高亮。结果区分余弦、BM25 和融合分数，支持展开完整片段、点击文件名打开来源；高亮按文本安全渲染。
- 分块保留解析正文的来源行号，检索与文档阅读共用来源坐标。回答引用合并为来源胶囊，可预览引用并定位文档；已完成回答的来源标注独立保存。旧分块缺少行号时不能据此恢复精确位置，也不承诺所有 PDF 都有页码。
- 新增飞书知识库只读连接，使用管理员配置的用户 token 搜索指定 Wiki 空间，并分页读取新版普通文档的实时纯文本。连接不在本地解析、同步或向量入库，token 到期需要管理员更换；共享连接使用配置身份的飞书权限，不能视为每位 Yuxi 用户各自的飞书授权。旧版文档、表格、附件与快捷方式不在阅读范围内。
- API 内置 `/api/mcp` 无状态 Streamable HTTP 服务，与 Agent、CLI 和 Public HTTP 复用五个只读知识工具：列库、检索、按文件名搜索、打开正文和文内查找。MCP 采用 API Key 认证并执行绑定用户的知识库读取权限，返回结构化结果及分页信息。
- 新增“知识库问答”预设。知识检索失败保留工具错误状态，正常空结果保持成功；文档批次中存在失败文件时，后台作业报告失败和有限明细。索引删除与清理以 PostgreSQL 可见事实过滤，减少旧索引及处理中间态对结果的影响。

配置与限制见[知识库 API](../../advanced/knowledge-base-api.md)和[知识库 MCP 接入](../../advanced/knowledge-mcp.md)。本节合并[Milvus 3 检索](../decisions/implemented/2026-10-02-milvus-3-text-retrieval.md)、[来源行号](../decisions/implemented/2026-10-09-chunk-source-lines-and-retrieval-preview.md)、[MCP](../decisions/implemented/2026-10-15-knowledge-mcp.md)及[飞书连接](../decisions/implemented/2026-10-16-feishu-readonly-connector.md)的最终行为。

## Agent、Skills、权限与身份

- 主 Agent 默认私有，所有者可管理；管理员可按授权共享，系统管理员可治理共享资源。角色限定可管理的能力，资源范围限定可访问的对象；模型请求、工具调用与恢复执行会重新核对当前授权，前端隐藏入口不代替后端授权。
- 资源选择统一使用“全部”或明确列表，空列表表示不选择。工具、知识库与共享 Skills 默认全部，MCP 和预加载 Skills 默认不选择；实际运行始终与当前用户的授权取交集，个人 Skill 保留在个人工作区。
- 没有已保存偏好时，Memory 默认开启，设置页提供“查看 Memory”入口；用户已明确保存的关闭状态继续生效。
- Agent 支持绑定专属 Skill，创建时可导入 Skill ZIP。远程 MCP 清单由独立的 MCP 管理入口创建，开放后可在 Agent 配置中选择。共享与专属 Skill 支持在线编辑完整包，保存时检查修订冲突，避免覆盖他人更新；远程安装草稿区分可确认条目与失败项，支持部分失败处理。
- 用户目录区分系统用户与 APP 终端用户。Agents API Key 绑定 APP，终端用户、Thread、附件与执行按 APP 作用域隔离；移除模拟他人登录入口。账号管理维持至少一个有效系统管理员，角色调整只升不降。
- 完善 OIDC discovery、JWKS、PKCE、回调及身份绑定校验，提供独立 Keycloak 联调指南。退出登录撤销 Yuxi 本地凭据，不主动退出企业认证中心；配置与部署条件见[统一认证](../../advanced/configuration.md)及[Keycloak 联调](../../advanced/keycloak-lab.md)。
- 反馈以已完成 Turn 的最终 Run 为对象，支持用户赞/踩、Agent 改进标记及系统管理员只读查看。消息级旧反馈接口与满意度统计保持移除，见[Agent 反馈](../../advanced/agent-feedback.md)。

权限边界见[资源权限](../../mechanisms/resource-permissions.md)，安装与编辑见[Skills 管理](../../agents/skills-management.md)。本节合并[资源权限](../decisions/implemented/2026-10-03-resource-permission-convergence.md)、[专属 Skill](../decisions/implemented/2026-10-03-agent-bound-skill.md)、[完整内容提交](../decisions/implemented/2026-10-05-skill-content-commit.md)及[OIDC 边界](../decisions/implemented/2026-10-13-oidc-production-boundaries.md)的最终行为。

## 图片、交付物与工作区体验

- 对话通过内置 `chat-widgets` Skill 按需展示图表、图片及图片组，沙盒图片可使用实际虚拟路径。工具结果中的文本与图片按原顺序显示，受保护图片通过统一鉴权读取，支持放大查看。截图进入聊天正文与文件登记为交付物是两个独立动作。
- 修复最终正文被过程折叠隐藏、交付卡片与重复过程展示的问题。图片缩略图限制展示高度；文件预览、下载与 Agent 实际读取的用户挂载保持一致，Skill 投影缺失时明确失败。
- 新建 Project 的默认工作目录使用 `projects/YYYYMMDD/<六位标识>`，重名时添加后缀；手动选择的目录继续按用户工作区边界校验。用户环境变量在每段 Run 开始时读取为快照，同次执行的命令使用同一份配置。
- 模型、审批、附件和项目选择入口共用弹层行为，模型目录显示加载与失败重试；主题、图标、头像及扩展卡片的外观统一。修复快速切换预览、全局搜索、上传期间切换会话及会话路由的迟到响应问题。
- 提供浏览器自动化 Skill 推荐，分别连接上游 `agent-browser` 与 `playwright-cli`。安装 Skill 后仍需按其指南在用户 VM 安装 CLI 依赖；跨会话登录状态由实际 profile/session 配置决定，不能视为默认永久保留。

对话内 HTML Preview 已移除，旧 `html:preview` 围栏显示为普通代码；HTML 文件仍可作为交付物在文件预览中打开。Widget 的 Button 及依赖提交操作的 Form/Input/Textarea/Select 不在当前协议内，模型生成这些节点会显示错误。知识库思维导图、旧 SubAgent 专用后端/目录及身份操作日志机制也已移除，知识图谱继续提供。

## 运行与工程维护

- 后端收敛为 `backend/yuxi` 单包，按业务域组织 services、repositories 和 models；API、worker、基础设施与 Schema 初始化保持明确边界。前端统一为 `frontend/`，按 app、pages、modules、shared 分层；自定义脚本和 Compose 命令需使用当前目录及服务名。
- 工具结果、审计、历史、用量与反馈围绕明确的 Turn/Run 事实读取，减少独立工具表和重复内容投影。后台作业统一为 BackgroundJob；PostgreSQL 持久意图、执行 owner 与租约拥有恢复结果，Redis 负责投递与短期事件。
- 文档解析生成完整 Markdown 目录，图片等资源随目录发布，上传、OCR、预览与文件操作在各自边界校验。共享存储查询限制并发，worker 和 API 保持可观察的启动、失联与关闭结果；readiness 不替代真实业务验证。
- 质量检查覆盖工程契约、后端 unit、Ruff、Web、依赖审计、文档及真实运行链路。开发分支匹配 `develop/0-8-0`，运行链路需要带 `yuxi-cube` 标签且能访问执行节点与共享文件的自托管 runner。
- 更新文档解析、MCP、Vue、HTML 清理及 YAML 等依赖的安全补丁，并同步生产锁文件；Markdown 自动链接和公式渲染依赖的已知告警已修复，生产依赖审计无已知漏洞。

## 候选验证与已知限制

本页描述候选源码的变化，不表示 tag、GitHub Release 或 npm 包已经发布。最终测试命令与结果见[发布准备记录](../decisions/implemented/2026-10-16-080-beta-release-preparation.md)和[本地生产验收](../decisions/implemented/2026-10-16-production-release-acceptance.md)，候选交付需要对应提交的检查结果。

- 全新生产核心拓扑与应用成套冷备恢复已在本地合成数据上验收；公网 TLS、真实数据规模和执行节点完整重启/VM 磁盘恢复仍需现场验收。
- 确定性协议重放验证调度、权限和文件结果，一次真实 SiliconFlow 流式探针通过；其他供应商、嵌入/重排质量、真实飞书撤权与所有文档类型需要各自验证。
- 自动入库作业完成后自动更新文件列表与统计，同库旧响应不会回退状态；验证见[列表终态刷新记录](../decisions/implemented/2026-10-16-knowledge-job-list-refresh.md)。
- 部分管理页面在窄屏仍存在布局限制；浏览器操作需要覆盖实际部署、主题和适用宽度，不能仅根据前端构建认定体验通过。
- 生产依赖审计只代表检查时已公开的漏洞信息；依赖更新与公式渲染兼容性验证见发布准备记录。
- 尚未实现的方向见[开发路线图](../roadmap.md)。提案、已被后续决定取代的中间 Schema/沙盒行为，以及 0.7.3 已包含的修复不重复列为 0.8 新功能。
