# 0.8.0 更新说明

本页面向准备试用或部署 0.8 的用户、管理员与集成开发者，汇总相对 `v0.7.3` tag 的变化。内容截至 2026-10-23 的已提交实现（`97e04174`），不包含工作区未提交改动；正式发布范围以对应 tag 和 GitHub Release 为准。

0.8 围绕“接入知识 → 分工执行 → 人工干预 → 核对来源与交付结果”完善工作流程，提供 Public API、CLI 和知识库 MCP，并增加无需 KVM 的容器执行选项。下文先说明部署及兼容变化，再按使用场景介绍能力与限制。

更新项按用户可观察的结果合并，连续修复和内部重构不重复列为功能。定时任务、用户 Memory、主动上下文压缩、基础子智能体、API Key 和执行审计是既有能力，本页只列出相关增强。历史版本见[版本变更记录](../changelog.md)。

## 升级概览

| 方向 | 主要变化 | 使用价值 |
| --- | --- | --- |
| 多智能体协作 | 成员使用独立会话，可分派任务、互发消息、等待结果并共享项目文件 | 将复杂任务分工处理，分别查看成员状态和结果 |
| 排队与人工干预 | 输入独立持久化；普通消息顺序执行，运行中可优先引导；支持逐条取消、停止全部和继续队列 | 补充要求、纠正方向，并控制后续任务的执行 |
| 检索与溯源 | 向量、BM25 和混合检索，配合关键词约束、高亮、正文行号和可独立选模的来源标注 | 兼顾语义与精确词查询，并从答案继续核对原文 |
| 知识接入与开放 | 飞书在线只读连接；内置五个只读知识工具的 MCP 服务 | 使用已有飞书资料，并让外部 Agent 查询 Yuxi 知识库 |
| Agent 与 Skills | 私有与授权共享、专属 Skill、中文展示名导入、完整包编辑及专属历史恢复 | 将提示、脚本和模板组织为可复用能力 |
| 身份与工具授权 | 完善 OIDC、资源权限和 APP 作用域；远程 MCP 支持个人 OAuth 连接 | 管理团队访问范围，并按个人授权使用适配的远程服务 |
| 执行环境 | 默认每用户持久 Cube VM；可选每 Run 临时容器 | 按隔离与持久化需求部署，可信场景无需 KVM 也能执行命令 |
| 文件与交付 | 个人空间文件夹上传、多图输入、图表、图文卡片和简短表单 | 保留目录结构，收集任务条件并查看文件和可视化结果 |
| 入口与管理 | 首页草稿交接、统一品牌、系统概览、模型检查和 Turn 调试 | 更快进入任务，并定位用量、运行与反馈问题 |
| 集成与可靠性 | Public v1 Session 协议、npm CLI、断流恢复、明确失败状态及只读历史 | 接入应用和脚本，并保留任务结果与工作记录 |

具体能力及适用边界见下文；飞书连接使用管理员配置的身份，个人 MCP OAuth 的供应商兼容性需逐项验证。

## 部署与兼容范围

::: warning 部署边界
0.8 面向全新部署，不提供从 0.7.x 或开发期旧数据库原地升级的程序。重要数据先成套备份 PostgreSQL、MinIO 和用户文件，并保留原部署。请使用独立数据目录试用，不能通过修改 Schema 版本标记绕过检查。
:::

- **数据库与共享初始化**：本页对应的已提交 Schema 基线为 business 1、knowledge 1。`app-init` 在锁内初始化空库，并同步系统配置、内置供应商、Agent、MCP 与 Skills；兼容库可重跑共享同步。API 与 worker 等待其成功后启动，不再各自写入共享定义。版本相同也不代表开发期旧库结构兼容，不能仅凭 `1/1` 判定可直接使用。操作以[生产部署](../../advanced/deployment.md)和[基线决定](../decisions/implemented/2026-10-19-schema-baseline-one.md)为准。
- **索引与对象存储**：Milvus 与 PyMilvus 切换到 3.0.2，配套 etcd 3.5.25、Woodpecker 日志队列与 MinIO 对象存储；MinIO 使用仓库 Dockerfile 构建的固定版本镜像。旧索引与对象不提供自动转换。
- **执行后端可选择**：`SANDBOX_BACKEND` 默认 `cube`，需要 CubeSandbox 0.7.3 的 Linux/KVM 节点；新增 `container` 使用独立 `sandbox-runner`，通过 Compose 的 `container` profile 启用。两种后端的持久化、挂载和隔离范围见[执行环境](#执行环境-cube-与容器)。旧 provisioner 接口不恢复，Docker socket 只交给 runner，API/worker 不持有它。
- **路径与环境数据**：运行时工作区路径统一在 `/home/user/workspace` 下，共享 Skill 授权投影为只读 `/home/user/skills`；个人 Skill 位于用户工作区。旧挂载路径、附件引用和 checkpoint 不自动转换。持久文件与环境内临时文件的保留范围取决于所选后端。
- **外部客户端**：Agent 对话统一使用 `/api/v1/agents/sessions` 资源、Input 回执和公开事件；知识库查询统一使用 `/api/v1/knowledge/tools`。旧 Conversation、external 查询入口及响应字段不保留兼容层，集成方应按[Agents API 快速开始](../../intro/agents-api-quickstart.md)和[知识库 API](../../advanced/knowledge-base-api.md)调整客户端。
- **命令行**：CLI 改为 Node.js 22+ 的 npm 包 `@xerrors/yuxi`，仓库内包版本为 0.1.0，独立于应用版本发布；源码版本不代表 npm 已发布。旧 Python CLI 的 TOML 配置不自动导入，新 CLI 使用 `~/.yuxi/config.json`，需要重新配置实例并登录，见[CLI 使用指南](../../intro/cli.md)。
- **自定义品牌**：产品名称、Logo、首页口号和登录背景统一由 `branding` 配置，页脚由 `footer` 配置；旧 `organization` 和副标题字段不再消费。已有自定义 YAML 需按[品牌配置](../../advanced/branding.md)调整。

新 CLI 提供多实例配置、API Key/浏览器登录、身份状态、Agent 目录、终端聊天与 SSE 恢复、附件及图片提交、知识库查询和 JSON 输出。附件先通过 `file upload` 上传草稿，再用 `thread send` 提交；旧 CLI 的 eval、Langfuse、本地 HTML Chat 与原 `upload` 命令不保留，审批与回答等待点需在网页继续。

## 会话、排队与多智能体协作

- **复杂任务可以分工处理**：协作成员拥有独立上下文和 Session，可创建子会话、互发消息、提交工作、等待并读取指定任务结果。新成员接收明确的任务描述，成员共享 Project 工作目录及整树四个执行名额，等待协作时释放执行资源。
- **用户可以进入具体成员推进工作**：协作列表展示成员层级、运行状态和人工待办，支持在侧栏打开成员会话回答问题、审批或发送引导。输入区可提及当前用户可运行的 Agent，由当前智能体按任务需要创建协作会话。
- **追加任务与调整方向分别处理**：每次提交保存独立 Input 和幂等回执，消费后生成正式消息与执行记录。普通追加输入按 FIFO 单条派发；运行中可用 steer 调整方向，连续就绪的 steer 在模型调用或工具批次完成后的安全边界合并处理。已经发往外部工具的操作不会因 steer 自动撤销。
- **停止与继续有明确范围**：待处理输入可逐条取消或转为引导；取消单个 Turn 只影响该任务，“停止全部”取消整树在途工作并暂停排队输入。显式继续队列会重新派发待处理工作。等待用户回答或审批时，普通提交被拒绝，需先处理对应等待点。
- **刷新与切换后保留正确的工作记录**：历史分页、实时流和断线恢复使用同一会话内容投影，最终结果读取指定 Turn 的 result Run。修复串会话更新、恢复后旧事件收尾及排队图片、附件归属问题；切换会话保留各自草稿、侧栏和滚动状态。
- **首条发送与审批失败保持当前状态**：新建页交接到正式会话时复用原视图，已接收、尚未消费的首条输入持续可见，并保留对应取消入口；创建失败恢复提交草稿。审批请求失败只显示错误，原等待点尚未消费时可重试；若新 Run、新等待点或终态已到达，不再用旧快照回滚页面。
- 新会话可在首次执行时自动命名。默认最大执行步数调整为 2000、上下文压缩阈值为 256K；已有显式配置继续优先。模型重试与摘要失败保留真实失败状态。
- 定时任务编辑器改善 Agent 搜索选择、名称焦点和频率布局；刷新项目列表时保留侧栏已有内容。定时执行是既有能力，这些变化改善配置与查看体验。

操作说明见[会话协作](../../agents/session-cooperation.md)，运行状态与恢复语义见[Agent 运行机制](../../mechanisms/agent-runtime.md)。交互变化的边界见[首条发送](../decisions/implemented/2026-10-20-session-send-layout.md)、[审批失败](../decisions/implemented/2026-10-23-approval-failure-preserves-current-run.md)和[定时任务编辑器](../decisions/implemented/2026-09-12-scheduled-agent-editor.md)。

## 知识检索、来源阅读与飞书连接

- **语义问题与精确词查询可以分别配置**：Milvus 知识库支持向量、BM25 与混合检索，可配置必含词、排除词、完整短语及高亮，适用于术语、型号、编号等需要保留精确词的查询。结果区分余弦、BM25 和融合分数，支持展开完整片段、点击文件名打开来源。
- **从回答继续核对来源**：分块保留解析正文的来源行号，检索与文档阅读共用坐标；回答通过来源胶囊预览引用并定位文档，已完成回答的来源标注独立保存。旧分块缺少行号时不能恢复精确位置，也不承诺所有 PDF 都有页码。检索质量仍需用实际语料和模型评估。
- **来源标注可独立选择模型**：超级管理员可设置来源标注模型，留空使用快速响应模型。标注按需处理已完成回答的正文、图片与表格，排除代码、公式、原生 HTML 和 Chat 组件；已有标注回读时也过滤这些范围。标注失败可重试且不改写原回答；图片引用表示来源或图注匹配，不等同于核验图片像素。关闭思考需使用所选供应商支持的模型参数，系统不自动为所有模型关闭思考。
- **飞书已有资料可以在线读取**：新增飞书知识库只读连接，使用管理员配置的用户 token 搜索指定 Wiki 空间，并分页读取新版普通文档的实时纯文本。连接不在本地解析、同步或向量入库，减少维护文档副本的步骤。token 到期需管理员更换；共享连接使用配置身份的飞书权限，旧版文档、表格、附件与快捷方式不在阅读范围内。
- **外部 Agent 可以使用 Yuxi 知识库**：API 内置 `/api/mcp` 无状态 Streamable HTTP 服务，与 Agent、CLI 和 Public HTTP 复用五个只读知识工具：列库、检索、按文件名搜索、打开正文和文内查找。客户端使用 API Key，按绑定用户的知识库权限读取结构化结果与分页信息，无需另起 MCP 服务进程。
- 新增“知识库问答”预设。知识检索失败保留工具错误状态，正常空结果保持成功；文档批次存在失败文件时，后台作业报告失败和有限明细。自动入库结束后刷新文件列表与统计，索引结果按 PostgreSQL 当前可见文件过滤，避免已删除文件的残留向量继续进入结果。
- **文档解析与图谱构建更容易定位问题**：支持旧版 `.xls` 多工作表转 Markdown，保留文本编号与 `NA` 等字面值，不保留嵌入图表或 Excel 显示样式。PDF 预览与预检修复资源加载、快速切换和页面释放问题；解析生成的图片等资源随 Markdown 目录发布。图谱抽取可配置单次模型调用超时，异常超长实体及关联关系被丢弃并记录数量，避免一个坏值使整块写入失败。图谱仍是既有能力，使用见[知识图谱](../../advanced/knowledge-base-graph.md)。
- 离线 HTML 可显式设置单文件参数 `html_text_only`，只提取正文、图片替代文本及视频链接，不读取缺失图片或视频封面；原 HTML 保留。默认解析仍要求图片完整并校验路径，正文模式不识别图片内文字，见[HTML 正文提取](../decisions/implemented/2026-10-18-html-text-only-parsing.md)。
- 知识库 URL 抓取在实际建连时校验 DNS 解析结果并连接已验证地址，拒绝私网、元数据地址和解析失败；重排模型响应校验结果索引，避免文档与分数错配。

配置与限制见[知识库 API](../../advanced/knowledge-base-api.md)和[知识库 MCP 接入](../../advanced/knowledge-mcp.md)。检索与阅读边界见[Milvus 3 检索](../decisions/implemented/2026-10-02-milvus-3-text-retrieval.md)、[来源标注模型与内容范围](../decisions/implemented/2026-10-23-reference-model-and-content-scope.md)及[飞书连接](../decisions/implemented/2026-10-16-feishu-readonly-connector.md)。

## Agent、Skills、权限与身份

- **Agent 可按团队需要私有使用或授权共享**：主 Agent 默认私有，所有者可管理；管理员可按授权共享，系统管理员可治理共享资源。角色限定可管理的能力，资源范围限定可访问的对象；模型请求、工具调用与恢复执行重新核对当前授权。
- 资源选择统一使用“全部”或明确列表，空列表表示不选择。通用配置中，工具、知识库与共享 Skills 默认全部，MCP 和预加载 Skills 默认不选择；实际运行始终与当前用户的授权取交集，个人 Skill 保留在个人工作区。默认助手的预加载选择见下文。
- 没有已保存偏好时，Memory 默认开启，设置页提供“查看 Memory”入口；用户已明确保存的关闭状态继续生效。
- **操作方法和配套文件可以随 Agent 复用**：Agent 支持绑定专属 Skill，创建时可导入 Skill ZIP；共享与专属 Skill 支持在线编辑完整包，保存时检查修订冲突，避免覆盖他人更新。专属 Skill 还支持显式发版、查看和恢复完整历史包，恢复覆盖当前文件与依赖；普通 Skill 不提供历史版本入口。远程安装草稿区分可确认条目与失败项，支持部分失败处理。
- **中文或带空格的 Skill 名称可以直接导入**：外部包未提供机器标识 `slug` 时，系统保留展示名并派生合法标识；显式提供的非法 `slug` 仍被拒绝。共享安装重名时分配后缀，个人安装保持同名拒绝；界面展示具体业务校验原因，底层异常继续脱敏，见[展示名导入决定](../decisions/implemented/2026-10-23-skill-import-display-name-slug.md)。
- 新建默认“智能助手”预加载 `chat-widgets` 和 `knowledge-base` 两个 Skill，让首轮即可获得组件展示和知识检索说明；已保存的 Agent 配置保持用户选择。预加载仍受当前用户权限及依赖工具授权约束。
- 用户目录区分系统用户与 APP 终端用户。Agents API Key 绑定 APP，终端用户、Thread、附件与执行按 APP 作用域隔离；移除模拟他人登录入口。账号管理维持至少一个有效系统管理员，角色调整只升不降。
- 完善 OIDC discovery、JWKS、PKCE、回调及身份绑定校验。退出登录撤销 Yuxi 本地凭据，不主动退出企业认证中心；配置与部署条件见[OIDC 认证](../../advanced/third-party-auth.md)。
- Agent 被删除或撤回访问后，原用户仍可读取自己已有会话的历史，输入与继续执行入口进入只读状态。网络或服务错误单独提供重试，历史读取继续遵循原用户和 APP 权限。
- 反馈以已完成 Turn 的最终 Run 为对象，支持用户赞/踩、Agent 改进标记及系统管理员只读查看。改进记录工具明确覆盖用户纠正、反复不满意、工具失败和能力缺失，允许记录尚未解决的问题；是否记录仍受模型行为影响。反馈不会自动训练或修改 Agent；消息级旧反馈接口与满意度统计保持移除，见[Agent 反馈](../../advanced/agent-feedback.md)。

权限边界见[资源权限](../../mechanisms/resource-permissions.md)，安装与编辑见[Skills 管理](../../agents/skills-management.md)。本节合并[资源权限](../decisions/implemented/2026-10-03-resource-permission-convergence.md)、[专属 Skill](../decisions/implemented/2026-10-03-agent-bound-skill.md)、[完整内容提交](../decisions/implemented/2026-10-05-skill-content-commit.md)及[OIDC 边界](../decisions/implemented/2026-10-13-oidc-production-boundaries.md)的最终行为。

## 远程 MCP 与个人账号授权

- 超级管理员统一配置远程 MCP，开放后在 Agent 配置中选择。共享 headers 模式使用配置身份；个人 OAuth 模式由每名用户连接自己的资源账号，平台登录与资源授权分别管理。
- 用户在扩展页面查看、连接和断开本人账号。个人凭据在服务端加密保存，刷新与断开按用户连接串行处理；实际调用重新检查当前用户、服务配置、工具开关和连接。未连接服务不进入可用工具集合，普通聊天继续；相关 Skill 的依赖在执行边界校验。
- **单个 MCP 故障不再中断普通聊天**：工具发现时，缺少凭据密钥、凭据不可解密或远端不可用会关闭该服务及依赖工具，并在状态面板显示可回读的原因。失败服务在同一 Run 内不重复发现，新 Run 重新检查；调用故障返回安全的工具错误。管理页连接测试仍报告失败，取消信号及外围身份、授权错误不会被转换为普通警告，见[MCP 故障隔离](../decisions/implemented/2026-10-20-mcp-runtime-degradation.md)。
- 断开或修改授权配置使旧授权事务失效，个人授权不回退为管理员凭据。本地断开不等于远端供应商撤销授权，也不能收回已经送达远端的请求。
- 个人 OAuth 适用于当前发现、注册、PKCE 和传输约束下的服务；其他服务需分别验证。部署需要通用凭据密钥和固定回调来源，见 [MCP 集成](../../agents/mcp-integration.md)。

Yuxi 向外提供的知识库 MCP 与这里的远程工具接入是两条链路：前者让外部客户端读取 Yuxi 知识，后者让 Yuxi Agent 调用外部服务。个人连接及执行授权见[MCP 授权与运行身份](../../mechanisms/mcp.md)，未复验范围见[验证与已知限制](#验证与已知限制)。

## 模型与网络工具

- **新部署使用更新的内置默认模型**：默认对话模型与快速响应模型均为硅基流动 `deepseek-ai/DeepSeek-V4.1-Flash`。已持久化配置不自动切换；已有实例需在供应商页面获取并启用所需模型，再调整默认选择。该变化是内置配置更新，实际供应商可用性需通过实例检查，见[模型配置](../../intro/model-config.md)。
- 模型选择器将检查结果直接显示为“通过”或“异常”，可点击重查；检查期间显示加载状态并阻止重复请求，切换模型后丢弃旧模型的迟到结果。模型目录加载失败时提供重试。
- **外部网关可按用户归属模型用量**：供应商可显式启用“请求携带用户 ID”，聊天请求携带带时间戳和 HMAC 签名的用户标识；默认关闭，需配置专用密钥。它不覆盖知识抽取、评测等无用户身份的后台调用，Gemini 不支持此请求头，也不替代网关的配额与重放控制，见[按用户统计模型用量](../../advanced/model-usage-tracking.md)。
- 网络搜索设置集中管理搜索与正文抓取供应商及凭据，按实际配置绑定可用工具。支持 Tavily、DeepSeek 搜索和正文读取，以及豆包搜索；不同供应商的参数限制分别校验，使用见[工具系统](../../agents/tools-system.md)。

## 执行环境：Cube 与容器

两种后端共用文件工具、`execute`、审批、审计及 Run 生命周期，由部署管理员选择。Run 是一次执行段；引导接续可能在同一轮任务内创建新的 Run。

| 行为 | Cube（默认） | Container（可选） |
| --- | --- | --- |
| 部署前提 | CubeSandbox 0.7.3、Linux/KVM 节点、用户模板与共享目录 | Docker 执行节点、独立 runner、预构建镜像，无需 KVM |
| 环境归属 | 每用户一个持久 VM，同用户会话复用 | 每 Run 一个临时容器，Run 内命令复用 |
| Home 与软件 | 跨会话保留；显式重建会清除 | Home 与 `/tmp` 临时保存，容器销毁后丢失 |
| Shell 挂载 | 当前用户 Workspace 与只读授权 Skills | 当前 Project Workdir 与只读授权 Skills |
| 网络 | 用户 VM 默认禁止私网出口，可安装外网依赖 | 默认无网络；联网须显式配置 |
| 空闲与结束 | 结束当前 Run 的命令；无活动工作时默认五分钟后休眠 | Run 终态清理容器，工作目录文件保留 |
| 适用范围 | 需要用户环境持久化与 VM 隔离的部署 | 单租户、可信代码或本地开发；共享宿主内核 |

- **Cube 配置与维护**：Compose 为端口、模板和标准共享目录提供默认值，管理员仍需实际准备同一份共享文件，变量默认值不会创建挂载。设置页展示忙碌、休眠时长和空闲倒计时；磁盘用量手动查询，休眠时查询会唤醒环境。重建保留宿主 Workspace 和 Skills。嵌套开发节点支持空闲页上报以归还宿主驻留内存，逻辑超售额度不代表生产容量承诺。
- **容器能力有明确范围**：生产镜像需固定 digest，默认非 root、只读根和无网络；API/worker 通过认证 HTTP 调用 runner。Shell 看不到其他项目及工作区中的个人 Skill 目录，文件工具仍按用户权限访问工作区。跨 Run 安装的软件、登录状态和临时文件不会自动保留；需要联网的 Skill 受网络配置限制。没有活动 Run 的环境变量验证、独立远程 Skill CLI 安装不可用，设置页不提供 VM 重建或磁盘操作。
- **停止与接续等待清理确认**：Run 结束、失败、取消及引导让出执行时保留持久清理责任。Cube 清理所属命令，容器后端删除所属环境；清理未完成会阻止同会话的接续 Run 开始。容器命令超时或取消时停止并确认所属进程组；若执行流故障且无法确认局部停止，删除整个 Run 容器并显式报告失败。

配置见[Cube 沙盒运维](../../advanced/sandbox-operations.md)与[Container 沙盒](../../advanced/container-sandbox.md)，生命周期见[沙盒机制](../../mechanisms/sandbox.md)。两种后端不会在故障时静默切换，也不会回退到宿主执行。

## 图片、交付物与工作区体验

- **个人空间支持上传文件夹**：保留浏览器提供的根文件夹名与内部层级，按批次顺序上传；已有目录可合并，已有文件不覆盖。冲突在该批写入前拒绝，后续批次失败时保留已完成批次并报告数量。空目录不上传，自带 nginx 入口仍有 20 MiB 请求体限制，较大的单文件仍可能返回 413，见[个人空间文件夹上传](../decisions/implemented/2026-10-23-personal-space-folder-upload.md)。
- **图片可随问题直接提交**：单条消息支持最多 10 张图片直读；排队和会话切换保持图片与原提交归属。文件仍通过附件准备和确认链路进入工作目录。
- **结果可用图表、图片和图文卡片展示**：内置 `chat-widgets` Skill 按需展示图表、图片组及图文组合，沙盒图片可使用实际虚拟路径。工具结果中的文本与图片按原顺序显示，受保护图片通过统一鉴权读取，支持放大查看。截图进入正文与文件登记为交付物是两个独立动作。
- **任务条件可在简短表单中一次填写**：聊天组件支持文本输入、多行文本、单选、日期及提交按钮。提交作为独立普通用户消息继续任务，保留编辑器中的草稿和附件；发送中、失败和已发送有明确反馈。表单仅收集回答，按钮只支持固定的发送消息动作，不直接执行任意工具或业务写入；实际触发和输出仍受模型行为影响。
- 修复最终正文被过程折叠隐藏、交付卡片与重复过程展示的问题。图片缩略图限制展示高度；文件预览、下载与 Agent 实际读取的用户挂载保持一致，Skill 投影缺失时明确失败。
- 新建 Project 的默认工作目录使用 `projects/YYYYMMDD/<六位标识>`，重名时添加后缀；手动选择的目录继续按用户工作区边界校验。用户环境变量在每段 Run 开始时读取为快照，同次执行的命令使用同一份配置。
- 模型、审批、附件和项目选择入口共用弹层行为；主题、图标、头像及扩展卡片的外观统一。修复快速切换预览、全局搜索、上传期间切换会话及会话路由的迟到响应问题。“+”和“@”共用添加菜单，集中选择附件、图片和可引用资源。
- 提供浏览器自动化 Skill 推荐，分别连接上游 `agent-browser` 与 `playwright-cli`。Cube 用户模板预装 Python Playwright 与 Chromium，但不包含这两个 CLI，仍需按 Skill 指南安装。跨会话登录状态由实际 profile/session 配置决定；容器模式不承诺持久安装或登录态。

对话内 HTML Preview 已移除，旧 `html:preview` 围栏显示为普通代码；HTML 文件仍可作为交付物在文件预览中打开。知识库思维导图、旧 SubAgent 专用后端/目录、Agent 待办清单工具及身份操作日志机制也已移除；知识图谱和协作成员的人工待办继续提供。

本节合并[对话组件](../decisions/implemented/2026-10-12-chat-widgets.md)、[表单回答](../decisions/implemented/2026-10-17-widget-forms-and-composition.md)、[交付正文](../decisions/implemented/2026-10-15-chat-delivery-display.md)、[文件投影](../decisions/implemented/2026-10-16-runtime-file-projection-consistency.md)及[工具图片](../decisions/implemented/2026-10-16-tool-result-image-preview.md)的最终行为。

## 首页、管理统计与调试

- **从首页输入任务进入会话**：首页输入跨登录跳转交接到新建会话草稿，保留已有草稿并等待用户显式发送；首页本身不执行任务。产品名称、Logo、口号与登录背景统一配置，主题支持浅色、深色和跟随系统；背景动效与示例 Agent 轮播尊重减少动效偏好。
- **超级管理员在概览中查看资源与调用趋势**：调用卡片支持智能体、工具、Token、会话和模型统计，以及 14 小时、14 天、14 周范围；会话新增与活跃分别计数，不能相加。智能体会话分布可选累计、近 7 天、近 30 天和近 3 个月，摘要随所选范围变化。统计统一时间口径，并拒绝切换后迟到的旧响应。
- Cube 的活跃与总 VM 数来自执行节点实时只读查询，不从数据库登记状态猜测，也不因查询唤醒环境；容器模式沿用该指标入口返回受管容器数量。查询失败单独提示，不影响其他统计。概览移除重复会话分析及明细表格，保留反馈入口，见[概览统计决定](../decisions/implemented/2026-10-16-dashboard-overview-and-vm-stats.md)。
- **按完整轮次定位执行与反馈**：调试面板按 Turn 分组，并保留各 Run 明细，让审批恢复和引导接续归在同一轮。超级管理员可从调试或反馈跳转该 Turn 的 Langfuse Trace；缺少 Trace 或配置时明确不可用，目标项目仍由 Langfuse 授权，见[轮次观测](../decisions/implemented/2026-10-16-turn-debug-langfuse-navigation.md)。

首页交接范围见[首页入口决定](../decisions/implemented/2026-10-16-home-entry-screen.md)，品牌字段见[品牌配置](../../advanced/branding.md)。

## 运行与工程维护

- 后端收敛为 `backend/yuxi` 单包，按业务域组织 services、repositories 和 models；API、worker、基础设施与共享初始化保持明确边界。前端统一为 `frontend/`，按 app、pages、modules、shared 分层，并通过模块公开入口约束跨模块依赖；自定义脚本和 Compose 命令需使用当前目录及服务名。
- 工具结果、审计、历史、用量与反馈围绕明确的 Turn/Run 事实读取，减少独立工具表和重复内容投影。后台作业统一为 BackgroundJob；PostgreSQL 持久意图、执行 owner 与租约拥有恢复结果，Redis 负责投递与短期事件。
- Run 准入、终态发布、文件结果与环境清理收敛到各自的服务与持久事实，失败时不凭日志或队列状态推断成功。`/api/system/health` 仅表示进程存活；`/api/system/ready` 检查启动、数据库、Redis 和兼容 worker 的就绪事实，仍不替代真实业务验证。知识库、图谱和评估能力始终注册，重型解析依赖在实际解析时加载。
- **常规运行 CI 使用容器后端**：质量检查覆盖工程契约、后端 unit、Ruff、Web、依赖审计、文档及真实运行链路，开发分支匹配 `develop/**` 并保留路径过滤。常规系统测试在 GitHub 托管 Ubuntu runner 上装配 container 拓扑；独立 PostgreSQL/Redis 服务测试不依赖沙盒节点，Cube 托管探针保留手动入口。配置与证据见[容器运行 CI 决定](../decisions/implemented/2026-10-23-container-runtime-ci.md)；常规 CI 不证明 Cube VM 或共享挂载已经验证。
- 更新文档解析、MCP、Vue、HTML 清理及 YAML 等依赖的安全补丁，同步生产锁文件，并修复 Markdown 自动链接与公式渲染依赖的已知告警。历史审计结果及覆盖范围见[发布准备记录](../decisions/implemented/2026-10-16-080-beta-release-preparation.md)，发布时仍需按实际锁文件复核。
