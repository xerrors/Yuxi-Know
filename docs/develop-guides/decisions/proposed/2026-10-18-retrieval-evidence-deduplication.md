# 检索证据在模型上下文与引用中的去重

状态：proposed
类型：architecture
Owner：backend/yuxi/modules/agents/runtime/middlewares/summary.py

## 问题

连续检索可能依次返回 C1–C5 和 C2–C6。重复原文同时占用模型上下文和引用候选池。简单记录整个会话曾出现的 chunk ID，会在上下文压缩、结果卸载或进程恢复后错误省略模型已经无法读取的内容。

本文面向维护 Agent runtime 与引用服务的开发者，只提出设计，不改变现有检索、压缩和引用行为。大结果文件转存、行号口径与 thinking 协议不在本提案内。

## 提案

### 实现方案

原始检索结果继续由 PostgreSQL 工具审计保存，保留每次查询、排序、分数和完整结果。LangGraph checkpoint 及其摘要事件拥有恢复所需的执行状态。两者分别派生模型输入视图和引用候选视图；不增加一个可独立修改的永久 seen-ID 事实源。

证据身份使用知识库、文件、generation 与 chunk ID 的组合，正文哈希用于核对同一身份的内容。文档窗口使用文件、generation、真实范围和正文哈希。不同文件或 generation 的相同文字保留各自来源。相邻但不相同的 chunk 不做语义合并，部分相交窗口只在有真实位置映射时消除已覆盖范围。

模型输入的去重在实际上下文装配时执行：先应用 checkpoint 的摘要事件，再检查将发送给模型的正文与定位信息。对完整可见的同一证据只保留一份正文，其他检索结果保留命中 ID、排序与指向正文的引用；消息 ID、tool_call_id、工具消息配对及顺序保持不变。输入计量与压缩使用同一视图，产生新摘要后重新计算正文覆盖，防止引用指向刚被压缩掉的消息。

| 第二次检索发生时的可见状态 | C2–C5 的处理 | C6 的处理 |
|---|---|---|
| 首次五个片段的完整正文仍在模型上下文 | 返回命中信息及已有证据引用，正文不重复 | 返回完整正文与来源 |
| 首次结果只剩模型生成的摘要或文件占位 | 允许重新返回正文，曾检索过不等于当前可见 | 返回完整正文与来源 |
| 仅能证明部分原文范围仍在上下文 | 保留未覆盖范围；无法证明覆盖时保守返回 | 返回完整正文与来源 |

上下文中的摘要、片段 ID 或文件路径都不证明全文可见。模型需要重新查看已卸载或已压缩的证据时，沿用现有检索或文档打开工具。去重需要的原始证据索引可从持久工具审计重建；短期缓存丢失只影响性能。并行工具完成后按实际模型消息顺序确定正文归属，不由并发工具抢占全局 seen 标记。不同 Thread、协作成员与上下文分支分别计算覆盖。

引用服务从原始审计构造来源，不消费模型输入中的省略文本。本轮同一证据的重复命中归并为一个候选，保留其审计来源；引用展示序号与证据身份分离。先消除完全重复和有证据证明被完整覆盖的窗口，再按现有请求预算分批匹配回答与来源，合并有效引用。每一条摘录仍须逐字存在于原始证据，批次失败必须显式报告，不静默丢弃一批来源。

跨轮复用通过本次模型输入中显式带入的证据引用追溯：生成时将所用来源引用保存在该次模型审计 metadata 中，指向原始审计消息与证据身份，不复制全文。引用候选可包含本轮实际检索结果，以及这些显式带入本轮的历史证据；不自动扫描邻轮猜测来源。摘要中无对应原文的概述不自动升级为可引用证据。最终回答仍由 result_run_id 指向的顶层 Run 拥有。

读取历史证据与展示引用时重新检查当前资源权限。引用绑定生成时的 generation；文件更新或删除后，不能把旧摘录定位到新版本，阅读入口须明确显示版本失效或不可用。

## 替代方案

- 全会话永久 seen-ID 集合只能证明曾经检索过，不能证明当前上下文仍有原文，会在压缩后造成证据缺失。
- 从模型摘要提取已见 ID 受摘要遗漏和格式变化影响，不能承担程序状态恢复。
- 直接修改或删除持久工具消息会破坏查询审计、工具配对及引用回溯。
- 仅在引用模块去重不能减少 Agent 检索循环中的上下文占用；仅在模型输入去重不能控制引用池体积。

## 风险

现有压缩预览并不总有精确的原文范围映射，首期应保守保留无法证明重复的内容。真实模型是否停止重复搜索仍需实测；上下文去重只减少重复正文，不替代检索策略。跨轮证据 metadata 是新的生成归属契约，落地前需要真实 PostgreSQL、恢复和权限测试。
