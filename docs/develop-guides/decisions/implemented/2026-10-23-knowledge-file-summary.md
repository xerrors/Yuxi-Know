# 知识库文件状态、统计与失败详情

状态：implemented
类型：bug-fix
Owner：frontend/src/modules/knowledge/ui/KnowledgeFileSummary.vue

## 问题

文件夹内存在解析失败时，知识库外层摘要只显示待解析和待入库，用户无法发现失败。文件列表投影丢失持久化错误信息，重试按钮不能说明失败原因。平铺文件数、大小、Chunks 和 Tokens 挤占工具栏。

目标是用户能从知识库摘要发现全部需关注文件、定位对应列表、读取错误原因和查看紧凑统计。非目标是修复特定解析器、自动重试、重新解析或重新入库、改动权限模型及新增通用统计平台。

## 决策

### 实现方案

文件 repository 在同一聚合中读取整个知识库的有效文件数量、大小、Chunks、Tokens 及逐状态计数，排除目录与软删除节点。Manager/read model/HTTP 保留这些计数，并在文件列表传递已有 error_message；数据库记录拥有事实，前端不从当前页推算全库摘要。

文件工具栏显示一个需关注状态下拉入口和一个文件数下拉入口。需关注入口覆盖失败、待处理和处理中状态，错误高于警告、警告高于处理中；无需关注状态时隐藏，颜色之外提供可访问名称和菜单文字。状态菜单按状态筛选全库文件，面包屑旁以独立标签显示当前筛选状态，待处理批量动作沿用现有准入和参数弹窗。只读用户可查看和筛选，写操作保持管理权限约束。

文件数入口使用与需关注菜单一致的下拉容器展开大小、Chunks 和 Tokens；每次打开时复用知识库详情 GET 接口刷新已有统计，展示加载及失败反馈，不设置独立刷新按钮。现有入库流程拥有 Token 计数，文件 metadata 与既有聚合接口拥有展示值；界面不读取分块正文重新计数、不改写文件计数，也不新增重算接口或后台作业。

失败状态标签在悬浮或键盘打开时展示可选择、自动换行的纯文本原因，空原因明确提示未记录，不增加独立的行内图标按钮。读取错误不触发重试；浮层内及行末菜单提供现有重试动作。关注菜单与统计浮层互斥展开，选择状态后关闭菜单。

## 替代方案

- 继续平铺状态按钮：失败和更多状态使工具栏持续膨胀，不采用。
- 从当前目录或当前页计算摘要：隐藏其他目录及分页中的失败，不采用。
- 点击失败状态直接重试且不展示原因：无法诊断故障，不采用。
- 自动重试或自动重新入库：改变副作用及用户意图，不属于范围。
- 新增 Token 重算接口、后台作业和计数写回：既有 metadata 已满足展示，超出展示优化的必要范围，不采用。

## 后果

摘要始终来自全库有效文件，当前目录、分页和筛选不掩盖失败。历史 failed 与 error_indexing 合并显示，并沿现有状态筛选规则查询；未知有效状态以警告显示，已入库和目录不产生关注提示。管理动作保留后端授权，当前管理页面对只读管理员提供状态与错误阅读能力，不扩展普通用户的管理路由权限。

统计刷新只重新读取既有字段及其聚合。后台入库任务继续维护 Token 与 Chunk 计数，展示优化不改变算法、口径或数据库字段；失败状态计数与 error_message 是本需求必需的读取投影补充。

## 验证

真实 HTTP 与 PostgreSQL 验证其他目录的失败仍计入全库摘要、目录和软删除排除、错误原文完整传递，以及只读管理员可读取统计。特意使用没有正文分块但已有 Token/Chunk 计数的文件，反复读取详情后回查数据库，确认计数保留且不产生后台作业；展示读取不能偷偷重算。

前端单元测试覆盖严重度、健康隐藏、历史别名、未知状态和长错误纯文本。真实页面验证状态筛选、错误原因、长错误键盘滚动、互斥浮层，以及统计刷新仅调用既有 GET 接口。浅色、深色及 768/1024px 宽度覆盖核心浮层。后端 unit、前端 lint/build、工程契约、文档构建与差异检查提供回归验证。
