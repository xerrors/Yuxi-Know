# 反馈界面与状态精简

状态：implemented
类型：simplification
Owner：frontend/src/modules/session/model/sessionFeedback.js

## 问题

反馈采集需要保存用户评价和 Agent 标记并支持管理员回看；当前前端同时在共享 Store 与视图维护编辑开关，详情还展示多个内部 ID、实时运行状态并为每个会话缓存错误。关闭说明弹窗后没有二次编辑入口，将已保存正文复制成草稿也没有当前用途。

## 决策

### 实现方案

共享 Store 保留服务端记录、草稿、加载与写入状态和拒绝迟到读取的 revision；当前 Refs 视图单独拥有弹窗开关，成功保存返回布尔结果，由视图关闭弹窗。读取只更新持久记录，不复制为草稿；成功保存清空草稿，失败保留草稿。

管理详情保留完整说明、Agent、来源、记录与更新时间和原会话入口；删除内部 ID 与运行状态展示，以单个当前详情错误替代逐会话错误缓存，固定 Modal 宽度沿用 Ant 响应式约束，删除窗口监听。后端授权、最终输出校验、lease、幂等、Schema 与分页保持当前边界；既有响应字段暂保留，保留当前响应契约。多选原因、过滤与分页具有当前使用入口，继续保留。

## 替代方案

保留全部设计会继续产生重复的编辑 Owner。删除共享 Store 会破坏 KeepAlive 视图间的评价一致性和读取竞态；删除预设、筛选或分页会降低现有产品能力，因此收窄状态与详情展示。改成无说明的赞踩超出本次精简范围。

## 后果

赞踩、多选原因、选填说明、管理员筛选与分页和原会话入口保持可用。共享 Store 管理持久记录、草稿与请求，视图管理弹窗，不再维护第二个编辑开关。详情为单一选中记录保存错误；关闭或换记录使旧查询失效，迟到失败不能污染新的详情。
