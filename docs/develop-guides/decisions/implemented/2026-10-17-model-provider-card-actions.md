# 供应商卡片以模型选择为主要操作

状态：implemented
类型：feature
Owner：frontend/src/modules/settings/ui/ModelProviderManagePanel.vue

## 问题

管理员在模型供应商列表中的主要任务是选择和管理已启用模型。卡片摘要展示能力枚举、请求用户 ID 配置，并以整卡点击进入供应商配置，使模型选择依赖底部额外入口。

## 决策

卡片正文展示 Base URL 和“模型：已启用 N 个”，零模型明确显示 0。点击已启用卡片打开该供应商现有的模型配置弹窗。右上角设置按钮直接打开供应商配置，并阻止点击事件冒泡。未启用供应商沿用紧凑卡片，点击正文与右上角设置均打开供应商配置，不读取远端模型。凭证缺失状态保留。模型弹窗每次打开时自动读取远端候选模型，远端区域标题右侧提供刷新按钮；加载动画位于候选列表区域，原顶部“获取远程模型”按钮移除。

### 实现方案

模型供应商面板继续拥有摘要、当前供应商和两个弹窗的状态。卡片内覆盖正文的原生按钮支持鼠标、Enter 和 Space；独立设置按钮位于其上方，提供供应商名称的无障碍标签和可见焦点。两个入口复用现有的弹窗打开函数，不增加 API、配置项或持久化状态。远端读取复用既有 API，按供应商保存候选列表、在途状态和错误；同一供应商在途请求去重，跨供应商请求各自收敛。刷新期间保留旧列表并禁用候选操作，失败就地显示错误；空结果明确显示“暂无远端模型”，刷新可重试。

## 替代方案

保留底部“管理模型”入口并将卡片点击继续用于配置，可以维持原交互，但会重复主要操作入口并占用摘要空间。选择模型为主要操作、设置为次要操作符合管理员的任务优先级。仅首次打开自动加载可以减少远端请求，但重新打开时可能展示过期目录；选择每次打开读取最新目录，在途请求共享一次读取。

## 后果

已启用供应商配置通过右上角设置进入；未启用供应商可直接点击卡片配置并启用。请求用户 ID 和能力仍由原配置表单维护，列表仅省略其摘要。打开模型弹窗会读取对应供应商的远端目录；配置写入仅在用户执行保存、启停或模型操作时发生，继续使用既有接口与权限边界。

## 验证

[浏览器回归脚本](../../../../frontend/test/browser/modelProviderCards.js) 在真实页面使用固定 HTTP 夹具，核对正常、凭证缺失、零模型、未启用供应商的 DOM，并验证未启用卡片的鼠标及 Enter/Space 均进入正确配置且不读取远端模型，以及已启用卡片点击、设置点击、键盘操作、浅深色和 1440、1024、768px 布局。脚本断言设置入口不会同时打开模型弹窗，并核对打开弹窗不产生写请求；恢复旧整卡行为或删除设置按钮的事件隔离均会使相应断言失败。浏览器还通过延迟响应核对自动读取、列表加载动画、刷新后的实际模型替换、失败后的旧数据和重试、空结果，以及各验收宽度的刷新按钮位置。[状态单测](../../../../frontend/test/unit/modelProviderSaveActions.test.js) 验证跨供应商并发、重复打开时在途去重和错误恢复。前端 lint、unit 和 build 负责静态及既有逻辑回归。
