# 系统概览、会话统计与实时 VM 数量

状态：implemented
类型：feature
Owner：frontend/src/pages/DashboardView.vue

## 问题

管理员需要在同一概览中读取资源总量、调用与会话趋势、智能体会话分布和执行节点实时 VM 数量。独立会话页面、重复智能体分析和明细表格增加阅读层级；不同统计对象的时间范围与平均值口径需要明确区分。数据库登记状态不能证明执行节点当前 VM 状态。

## 决策

### 实现方案

`DashboardView` 统一装配响应式概览网格。顶部展示累计资源指标和实时 VM 数量，未归档会话与周期活跃会话使用不同标签；首行是调用统计宽卡和用户活跃度，下方是智能体会话分布、工具调用监控、知识库使用情况三列，窄窗口顺序换行。删除会话分析 Tab、会话明细审计、重复 AI 智能体分析、会话深度、高频用户和工具错误分析表格，以及失去消费方的前端组件、请求和格式化函数。旧 `tab=threads` 链接显示系统概览，智能体反馈入口保留；既有后端多维聚合及审计接口保留。

`DashboardChartCard` 统一摘要与内容区域的分隔、间距，调用、用户、分布、工具和知识库卡片共用。调用统计默认选择智能体，支持智能体、工具、Token、会话、模型五个 Tab，共用 14 小时、14 天、14 周范围、图表容器与绘制流程。摘要从当前时序序列计算总量、均值与峰值，工具接口的累计 `total_count` 不用于周期摘要。类型或周期切换按请求版本拒绝迟到响应。

`DashboardRepository` 拥有统计查询，Dashboard service 提供业务入口，超级管理员路由负责协议与授权。`GET /api/dashboard/stats/calls/timeseries?type=sessions` 按上海时间截整小时、日或周一，补齐十四个时间桶，周标签使用 ISO 周年与周号。新增会话按创建时间计数，活跃会话按桶内非审计消息去重会话计数，排除已删除会话、已删除用户和未来事件。新增与活跃可重叠，用分组柱而非堆叠柱展示，摘要与接口 total/average/peak 只统计新增；其他调用类型沿用既有查询边界。

`GET /api/dashboard/stats/agents/sessions` 独立提供累计、近 7 天、近 30 天、近 3 个月的新建会话分布。7/30 天按上海自然日包含今天，3 个月向前推三个日历月，月末回退到目标月最后一天；累计无开始时间。所有范围排除未来或已删除会话及已删除用户。平均消息数为选中会话截至当前的非审计消息总量除以会话数，包含零消息会话，排除未来消息，PostgreSQL 聚合值在读取边界转为 Python 数值。卡片摘要与前八位排行共用同一响应，切换范围隐藏上一范围数据并拒绝迟到响应，失败可独立重试；下拉范围只影响分布卡片。

新增超级管理员专用 `GET /api/dashboard/stats/vms`，由沙盒 service 调用 CubeAdapter 的只读控制面列表，返回 `active_vms`、`total_vms`。统计配置执行节点 `/v2/sandboxes` 返回的全部实例；`running` 为活跃，休眠等其他实例计入总数。查询不调用 connect、不创建或唤醒 VM。列表形状异常、连接失败和超时显式失败。前端独立加载 VM 指标，失败显示不可用与重试，其他统计继续展示。

## 替代方案

- 从 `user_sandboxes` 聚合：成本低，但外部暂停、删除和失联可能使当前计数失真。用户明确选择执行节点实时状态。
- 保留独立会话页面、趋势卡或重复智能体分析：继续分散阅读入口，与统一概览的要求冲突。
- 把新增和活跃会话堆叠或相加：两者可重叠，会把同一会话重复计入摘要。
- 固定 30 天或仅给原按天接口更换标签：不能提供小时与完整十四周数据，采用后端真实分桶。
- 修改旧多维聚合的范围语义：会改变既有消费者的累计口径，采用独立分布接口。
- 在前端过滤已返回的前几名：无法得到所选范围的完整会话数和加权平均值。
- 将 VM 请求绑定基础统计：控制面失败会使正常业务统计一起不可用，故独立查询。

会话统计 PostgreSQL/HTTP integration 的 9 项、VM HTTP integration 的 2 项及相关 service/unit 已通过。VM 测试使用自管临时账号并只读节点，不创建、暂停、唤醒或销毁实例；历史共享 Workdir 的清理保护保持生效。浏览器使用固定 API fixture，不能替代真实授权、数据库或 Cube 控制面证据。

`docker compose exec -T frontend pnpm run lint:check`、`docker compose exec -T frontend pnpm run test:unit`、`docker compose exec -T frontend pnpm run build` 与上述概览浏览器验证已通过。批量 API unit 断言四项统计结果与请求顺序，调试和列表相关回归继续由各自测试维护。

旧能力不存在：会话分析 Tab、独立会话趋势组件、明细抽屉、固定 30 天趋势入口、重复智能体分析、深度/高频用户/工具错误表格及无消费者的前端 API 不再装配；既有后端聚合与审计接口继续保留。

重新引入条件：存在明确不同于当前概览的分析或明细需求，并由新决定明确消费者、统计口径、权限和验证后再引入。

## 后果

管理员在一个网格中读取统计。主图表的范围由所有 Tab 共用，分布卡片按会话创建范围独立统计；平均消息数不能解释为完整对话轮数。累计资源指标、周期趋势与范围分布保留各自标签，后端旧聚合字段不再由此页面消费。

控制面数量是请求时刻的观察，页面加载或显式刷新后更新；控制面不可用时保留其他数据库统计。没有 Schema、业务写入或 VM 生命周期变更，既有后端调用者继续使用原聚合及审计契约。
