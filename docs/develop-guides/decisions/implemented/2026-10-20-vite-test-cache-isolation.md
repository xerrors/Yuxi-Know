# 测试 Vite 实例独占临时依赖缓存

状态：implemented
类型：bug-fix
Owner：frontend/test/helpers/createTestServer.js

## 问题

前端单测在开发容器内创建 Vite 实例，默认与长期运行的开发服务共用 `node_modules/.vite`。部分单测添加替身插件，改变 Vite 配置哈希；Vite 随后删除旧缓存目录。开发服务仍持有原模块图，尚未加载的模块因磁盘文件缺失而返回 `504 Outdated Optimize Dep`。正在使用的服务无需重启或升级依赖即可进入此状态。

## 决策

### 实现方案

单测通过 `createTestServer` 创建 Vite 服务。每次调用分配系统临时目录作为 `cacheDir`，保留调用方的插件、SSR 和服务选项，在服务关闭或创建失败时删除自己的缓存。开发服务沿用 Vite 默认缓存。共享入口由 `frontend/test/helpers/createTestServer.js` 拥有，单测中的服务创建调用全部使用该入口。

## 替代方案

显式预构建图形库不能阻止另一个实例删除缓存。开发服务和测试分别使用固定缓存目录可以隔离开发服务，但测试实例之间仍可互相覆盖。每次创建服务分配独立目录，使缓存生命周期与实例一致。

## 后果

测试服务需要各自执行冷启动依赖优化，增加测试启动成本。测试关闭时清理临时缓存；异常终止进程时仍可能留下系统临时目录。用户在此前缓存被破坏后需刷新页面，必要时重启前端服务以重建一致的模块图与缓存。

## 验证

故障重现使用独立临时目录中的两个 Vite 实例：第一个实例的 ECharts 依赖请求返回 200，第二个实例带不同插件执行 `ssrLoadModule` 后，共用缓存的依赖文件消失，第一个实例的未缓存请求返回 504 `Outdated Optimize Dep`。实验未修改运行中开发服务的缓存。

运行容器中发现 417 个预构建临时目录，集中在多个时段；源码中 37 个单测文件直接创建默认缓存的 Vite 实例。历史故障没有完整请求与文件变动时间线，因此不声称逐次证明用户此前所有报错均由此路径触发。

使用相同隔离诊断，将第二个实例改为经由 `createTestServer` 创建：其启动前后第一个实例的依赖请求均返回 200，依赖文件仍存在，两个实例的缓存目录不同，第二个实例关闭后自身缓存目录被删除。

实际诊断通过 `docker compose exec -T frontend node --input-type=module` 执行，在系统临时目录创建服务，以真实 HTTP 响应、依赖文件存在性和目录清理结果作为证据。按用户要求未运行单元测试套件或构建。
