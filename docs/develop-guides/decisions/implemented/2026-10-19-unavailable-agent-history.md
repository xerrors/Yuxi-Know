# 智能体不可用时保留只读历史

状态：implemented
类型：bug-fix
Owner：frontend/src/modules/session/ui/SessionWorkspace.vue

## 问题

对话和消息独立保存，但页面先请求智能体详情，智能体已删除或不可访问时提前退出，历史无法展示并重复报错。用户需要保留历史，在原输入位置统一显示“智能体当前不可用”，不显示输入框，也不在标题加标记。网络错误需要独立重试。

## 决策

### 实现方案

SessionWorkspace 独立加载历史与当前智能体可执行性；403/404 或 can_run=false 显示不可用，网络/服务错误显示加载失败与重试。智能体详情强制复核当前权限，对该预期失败由页面统一处理，避免 store 和页面重复提示。只读时隐藏输入与审批入口，关闭继续执行、消息交互和压缩动作；历史读取继续使用原用户/APP 边界，后端发送、恢复和压缩校验保持有效。不改 Session 状态、不改标题、不改绑其他智能体，不改删除和归档规则。

## 替代方案

删除对话会损失历史；仅禁用输入框不满足用户明确要求，且不能覆盖其他执行入口；把所有加载错误归为不可用会掩盖网络故障。选择派生的页面只读状态与现有后端边界。

## 后果

智能体可执行性是页面派生状态，不新增持久状态和接口。历史与执行权限独立：删除智能体或撤回访问不删除消息，发送、恢复和压缩仍由原后端权限检查拒绝。切换对话和重复重试采用请求代次与对话身份抛弃迟到结果。新建对话在首次提交前加载可执行性，首条提交失败后仍可重试。页面打开与重新激活增加一次最新详情请求，避免缓存权限继续控制执行入口；不增加轮询。

## 验证

- `docker compose exec -T frontend pnpm run lint:check`、`pnpm run test:unit`、`pnpm run build` 通过，前端 726 个单测通过。相关单测覆盖 403/404、`can_run=false`、503/网络失败重试、跨对话迟到响应、同对话重试竞态、历史加载及只读消息交互。
- Playwright 使用普通企业账号真实登录，创建隔离智能体与对话，经 worker 获取真实模型回答后撤销权限，再删除智能体。两种状态均保留原消息和标题、隐藏输入且没有重复错误弹窗；真实 HTTP 绕过 UI 提交消息、恢复、压缩返回 404，其他用户读取该历史也返回 404。超级管理员已有已删除智能体的考勤历史同样可读。
- 浏览器对详情请求注入 503 和断网，历史保持可读，显示独立错误，点击重试恢复输入。新建对话首条消息请求注入 503 后，输入与重试按钮可用；恢复请求后真实模型完成回答。夹具结束先归档对话再删除测试智能体，保留消息且不残留活动测试入口。
