# 嵌套 Cube 节点资源配置与空闲页回收

状态：implemented
类型：architecture
Owner：docker/cube/setup-node.sh

## 问题

用户 VM 休眠后，嵌套 Linux 节点的空闲页与文件缓存仍使外层 QEMU 保持较大 RSS；默认调度额度和实例数量限制也阻止百台轻量环境同时运行。部署目标是 QEMU 八核／24 GiB、容器八核／32 GiB，面向 100 台轻量 VM，同时保留既有账号、持久磁盘和休眠环境。

本记录合并 2026-10-19 的自动回收、粒度、预建池、节点扩容和两轮恢复决定，以最终配置为当前事实，保留关键实验条件与验证范围。

## 决策

### 实现方案

| Owner | 当前行为 |
|---|---|
| `docker/cube/compose.yml` | 容器 CPU 上限八核、内存上限 32 GiB |
| `docker/cube/run-vm.sh` | QEMU `-smp 8 -m 24576`，共享 memfd `size=24G`，启用 `virtio-balloon-pci,free-page-reporting=on` |
| `docker/cube/setup-node.sh --nested` | tmpfiles 持久设置 `page_reporting_order=1`；本机基础页 4 KiB，对应 8 KiB 上报块 |
| 同一嵌套安装入口 | 持久配置 Cubelet 逻辑 CPU 128000m、内存 128 GiB、实例总数 512、创建并发 4、休眠配额释放比例 1.0，并重启 Cubelet 加载 |

guest 内核将符合粒度的空闲页报告给 QEMU，QEMU 归还对应宿主驻留内存；节点配置容量保持，后续访问重新分配页面。文件缓存仍由 guest Linux 正常管理，不安装定时 `drop_caches` 或 balloon 目标容量控制。

逻辑配额允许轻量任务超售，不增加实际 CPU 或 RAM，也不是严格的 100 台运行数限制。休眠释放 CPU／内存额度，恢复时重新准入；休眠对象继续占实例数量和快照存储。应用排队、压力驱动的物理资源准入和跨节点迁移不属于本次改动。

原生节点不应用 `--nested` 的上报和逻辑额度配置。预建池属于节点持久磁盘内的 Cubelet 配置：本机 `pool_size=99`，v0.7.3 按包含上界的编号 0～99 预建每池 100 个槽位。仓库安装入口不修改新节点的预建池默认值，按需扩展由 Cube allocator 实现。

安装入口仅替换 `host.quota` 内的五个字段，兄弟段和其他配置保留。配置缺少目标段、缺少字段或存在重复字段时，在写入前显式失败。`scripts/test_cube_node_setup.py` 在临时配置中执行安装入口的实际编辑代码，覆盖这些拒绝原因、兄弟同名字段保留与重复执行结果。

## 替代方案

- 保留默认大块上报：减少处理次数，但较小的空闲块继续驻留。4 KiB 上报覆盖单页；当前选择 8 KiB，性能取舍仍需长期负载验证。
- 主动清缓存或缩小 balloon 容量：前者驱逐可复用快照缓存，后者改变节点可用容量并需要额外策略。当前使用空闲页自动上报。
- 保守调度额度：可以限制超售，但不能满足百台一核／1 GiB 模板同时运行的目标。持续计算或大内存负载需要降低密度或增加节点。
- 保留较大预建池：增加常驻内核对象开销。本机采用较小预建池并验证越界扩展，不承诺池自动收缩。

## 后果

八核／24 GiB 是运行 VM 共享的物理资源预算。高 CPU、全量内存写入或磁盘压力可能造成延迟、恢复拒绝或 OOM，逻辑额度不构成资源保证。32 GiB 是容器上限而非预留；guest 内存也可能先于外层容器耗尽。

QEMU RSS、容器原始 `memory.current` 和 guest `MemTotal − MemAvailable` 分别观测驻留、cgroup 记账和 guest 可用内存估计，不能互换。休眠后仍保留节点服务、文件缓存及未归还页。细粒度上报增加处理和重新分配成本，缓存回收也可能增加恢复读盘时延。

节点重启前需确认没有活动 VM、Run 和命令，正常关闭 QEMU，并保留持久磁盘与共享挂载。跨节点扩容需另外处理快照与 Workspace 可访问性；现有嵌套运行器定位为开发验证，原生 Linux/KVM 部署需重新校准配额与容量。
