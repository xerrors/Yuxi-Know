# 检索片段阅读与紧凑文件预览

状态：implemented
类型：bug-fix
Owner：frontend/src/modules/knowledge/ui/QueryResultChunk.vue

## 问题

结果卡片整体点击会打开侧栏，阅读或展开片段时容易误触。长片段占据过多列表空间；检索摘要使用大面积强调色。预览栏较窄时工具与文件名换行，压缩阅读区域。

## 决策

### 实现方案

QueryResultChunk 仅由文件名按钮发出 select。片段默认展示六行，实际溢出时提供独立展开/收起；带高亮的摘要可以展开为完整正文，文本均使用安全插值。文件名显示省略并通过 title 保留完整名称；缺少文件 ID 时保留只读来源名称。评分与块索引放在卡片底部，来源不再重复展示，文件 ID 留在数据和原有预览请求中。

QuerySection 使用紧凑、低强调的结果数量与清空入口。FileDetailModal 以自身容器宽度选择工具入口：超过 640px 时保留原视图与下载按钮，较窄时在“更多文件操作”菜单提供同一组视图和下载行为。嵌入预览和弹窗都设置对应的命名容器；关闭按钮保持独立。文件操作菜单的选中、悬停、禁用状态使用现有中性色 token，样式限定于此菜单。头部保持单行，文件名省略并提供完整标题。

## 替代方案

只按浏览器宽度切换无法覆盖宽屏中的窄侧栏。缩小所有按钮仍会挤占长文件名。继续整卡点击会混淆阅读和跳转。固定字符数不能准确反映不同宽度下的文本溢出，因此通过现有 VueUse 的 ResizeObserver 测量实际展示高度。

## 后果

用户可以连续扫描短摘要、独立展开全文，再通过文件名打开原文。查询请求、文件授权、下载用例与持久化保持原有链路。容器查询使用项目当前浏览器能力，不增加依赖。

## 验证

`docker compose exec -T frontend node --test test/unit/knowledgeQueryResult.test.js test/unit/knowledgePreviewState.test.js`：Passed，11 项通过，覆盖评分含零值、文本安全、文件名入口和查询响应归属。

实际 Vite 页面运行 `frontend/test/browser/knowledgeQueryReading.js`：Passed。正文和展开/收起均不打开预览，文件名支持键盘打开；长片段默认高度约 125px，展开后约 1518px，短片段没有多余按钮。缺少六行限制时实际高度检查会失败；恢复整卡跳转时正文点击检查会失败。

浅深色下在 1440px、1024px 和 768px 测量预览，头部均为 53px，文件名发生省略且无横向溢出；460px 窄侧栏使用菜单，668px/686px 容器使用完整工具栏。菜单四种视图均切换到对应实际内容；原文与 Markdown 下载已回读最终字节并核对完整内容，关闭和新查询状态通过。

前端完整 unit 619 项、lint、typecheck 和生产 build：Passed。菜单在浅深色下的选中背景、选中文字及悬停背景均与对应灰阶 token 一致，已核对截图。浏览器使用确定性 HTTP 夹具验证真实组件，不覆盖后端文件转换服务或真实知识库数据；相关后端链路没有修改。
